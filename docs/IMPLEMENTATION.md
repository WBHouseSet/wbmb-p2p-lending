# 구현 기록 — v0.1, 2026-10-01

`DESIGN.md`는 원본 연구 스냅샷이다. 그 문서의 ‘미구현’ 표기는 당시 상태이며 현재 구현 범위는 이 파일과 README를 따른다. 기존 autouniswap 운영 코드·지갑·서비스와 분리된 독립 프로젝트다.

## 구현 결정

- 게시글은 온체인 에스크로 방식. 차입자는 WBMB, 대출자는 USDT를 게시 시 잠근다.
- 각 부분 체결마다 독립 loan을 생성한다. 전체 담보를 참여자끼리 공유하는 풀은 없다.
- 대출자 게시의 필요 담보는 체결 시 가격으로 계산한다. 차입자가 확인한 `maxCollateral`과 체결 `deadline`을 강제한다.
- 차입자 게시의 담보는 **누적 비례 배정량의 올림 차이**로 배분한다. 원문의 체결별 올림을 그대로 반복하면 마지막 담보가 부족할 수 있어 누적 배분으로 보완했다. 모든 체결에 현재 담보비율 검사를 다시 수행한다.
- 금리는 고정 단리 APR. 각 체결부터 만기까지 ACT/365 Fixed, 이자에 이자를 붙이지 않는다.
- 원금 일부 상환에도 누적 이자는 전액 납부한다. 이자 나머지를 다음 계산으로 이월하고 최종 상환에 최소 토큰 단위로 올림한다.
- 수수료도 나머지를 이월해 반복 분할로 회피하지 못하게 하고 최종 상환에서 올림한다.
- 활성 대출은 담보 추가만 가능하다. 부분 담보 인출 기능은 없다.
- 만기+유예 이후에도 정산 전이면 상환할 수 있다. 부분 상환이나 추가 담보는 만기 연장이 아니다.
- 가격+만기와 만기만·전체담보 귀속을 별도 `Mode`로 구현했다. 사용자의 최종 상품 선택을 대신하지 않는 로컬 비교 기능이다.
- 모든 수령은 각 주소의 claimable 잔액에서 본인이 가져간다. 취소·만료 처리자가 수령 주소를 바꿀 수 없다.

## 회계 불변조건

```text
보유 USDT >= escrowUSDT + totalClaimUSDT + feeBalance
보유 WBMB >= escrowWBMB + activeCollateral + totalClaimWBMB
```

USDT 대출원금은 이미 차입자에게 지급됐으므로 보유 잔액에 더하지 않는다. 강제 직접 입금은 여분 자산이 되며 임의 회수 함수가 없다. 수수료 모듈은 대출 컨트랙트에서 `feeBalance`만 전달받는다. 이자 미납 상태에서 미리 공급자 수령 잔액을 생성하지 않는다.

자금 관련 외부 함수는 재진입을 막고, 전송 전 회계 변경 후 실패 시 전체 revert한다. SafeERC20 처리와 실수령 잔액 검사로 fee-on-transfer 토큰을 거부한다. 지급 실패는 claim을 소모하지 않는다.

## 가격 모듈의 정확한 범위

`src/prices.mjs`는 정렬된 30분 구간 336개, 양 소스의 양수 BigInt 가격, 누락/중복/만료/미래 구간, 조정계수, 소스 괴리를 검사하고 최저값을 계산한다. 데이터가 실제 거래소에서 왔는지 증명하는 모듈은 아니다.

`SignedPricePolicy`(v0.2, 2026-10-01 추가)는 `MockPricePolicy`를 대체한다. 보고서 구조체는 정책 ID·roundId·관측 시작/끝·유효기한·구간 수·DEX/LBank 각각의 7일 최저와 현재가(LBank는 조정 전 원값)·원자료 해시를 담고, 보고자들이 EIP-712로 서명한다. `submit`은 누구나 호출할 수 있고 컨트랙트가 다음을 검사한다.

| 에러                    | 거부 조건                                                                                                                                           |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BAD_POLICY`            | 정책 ID 불일치                                                                                                                                      |
| `OLD_ROUND`             | roundId가 직전 수용 값 이하 (재사용·되돌리기 포함)                                                                                                  |
| `ROUND_GAP`             | roundId가 직전 값 + 1이 아님 (잘못된 큰 번호로 정책이 영구 정지되는 것 방지)                                                                        |
| `BAD_WINDOW`            | 관측 끝이 1,800초 배수가 아님 / 미래 / 시작이 끝−604,800초가 아님                                                                                   |
| `BAD_VALIDITY`          | 유효기한이 이미 지남 / 관측 끝 + `maxAge` 초과                                                                                                      |
| `BAD_COVERAGE`          | 구간 수가 336이 아님                                                                                                                                |
| `BAD_PRICE`             | 가격 0·1e30 초과, 전환계수 적용 후 0                                                                                                                |
| `NOT_ENOUGH_SIGNATURES` | 서명 수가 임계값 미만                                                                                                                               |
| `BAD_SIGNER`            | 보고자 아님 / 중복 / 주소 오름차순 아님 / 다른 체인·컨트랙트·내용에 대한 서명. 형식이 깨진 서명은 OpenZeppelin `ECDSAInvalidSignature*` 에러로 거부 |
| `DIVERGENCE`            | 최저가 쌍 또는 현재가 쌍의 소스 간 차이가 한도 초과 (높은 쪽으로 대체하지 않음)                                                                     |
| `STALE_PRICE`           | `prices()` 호출 시 유효기한 경과 또는 보고서 없음                                                                                                   |

통과하면 `min(DEX, LBank×전환계수)`를 최저가·현재가로 저장한다. 보고자 집합(로컬: 노드 계정 4·5·6 중 2명)·임계값·전환계수·괴리 한도·`maxAge`는 생성자에서 고정되고 변경 함수가 없다. OpenZeppelin ECDSA/EIP712가 `mcopy`를 쓰므로 컴파일 대상 EVM을 Shanghai에서 Cancun으로 올렸다.

컨트랙트가 증명하지 **않는** 것: 서명된 숫자가 실제 거래소 관측인지, 336개 구간이 실제로 수집됐는지(`bucketCount`와 `rawDataHash`는 보고자의 주장), 보고자들의 독립성. 로컬 실험실과 테스트 헬퍼는 두 소스에 같은 합성 값을 넣어 서명하며, `rawDataHash`에는 구간 자료 해시가 아니라 `synthetic: true` 표시와 게시 값에 대한 해시(`hashSyntheticData`)를 넣는다. 유효기한은 관측 끝 + 2시간이라 게시 시점 기준 남은 유효시간은 1.5~2시간이다. 제출은 누구나 할 수 있으므로, 같은 round로 서명된 유효 보고서가 여럿이면 먼저 제출된 하나만 반영된다. ‘7일’이 실제 시장 관측이었다고 주장하지 않는다. 실험실은 모의 시간 이동 후 가격을 재등록하며 그 시점에 336개 과거 관측을 재구성하는 기능은 아니다. 모의 현재 가격을 낮추면 최저값도 낮추지만 7일 경계에서 오래된 저가가 제거되는 온체인 모듈은 아니다. 실제 rolling 계산은 입력 데이터에 대해 `prices.mjs`에서만 검증된다.

가격은 USDT 기본 단위(18 decimals) / WBMB 한 개이며 담보는 8 decimals다. 체결 한도는 `min(weekLow,current)`를 사용한다. 청산은 current를 사용한다. 오라클 유효기간 2시간은 체험용이며 실운영 추천값이 아니다.

## 소각 모듈의 정확한 범위

`MockFeeBurner`는 테스트 WBMB를 미리 지급받은 모의 교환기다. 모의 가격에 따라 수수료 USDT를 고정 sink로 보내고 자신이 가진 mock WBMB의 `burn()`을 호출한다. 실제 DEX 거래·실제 WBMB burn 지원·원본 BMB 소각을 구현하거나 검증한 것이 아니다.

실제 모듈은 교환 라우터/경로 고정, 시세/슬리피지/최소 수령량 검증, MEV 방어, 실제 토큰 burn 또는 영구 잠금 방식, 가스 재원을 별도로 확정해야 한다. 현재 컨트랙트에는 모의 소각기를 교체하는 관리자 함수가 없으므로 실운영은 새 검토·새 배포가 필요하다.

## 카운슬 가격형 시장 (v0.3, 2026-10-02)

미상환·담보가치 하락 때 **부채에 보너스 10%를 더한 만큼의 WBMB만** 대출자에게 주고 나머지 담보는 차입자에게 돌려주는 세 번째 시장이다. 가격은 모빅 카운슬 가격이고, 사람이 돌리는 중계 봇이 그 값을 `CouncilPricePolicy`에 옮겨 적는다. 설계와 근거는 `docs/superpowers/specs/2026-10-02-council-price-liquidation-design.md`, 운영 방법은 [MAINNET.md](MAINNET.md) 8절. 아직 배포하지 않았다.

### CouncilPricePolicy

`IPricePolicy`를 구현한다. `SignedPricePolicy`의 EIP-712 서명 검증과 순차 round 방식을 가져오고 7일 구간·두 소스 비교는 뺐다. 보고서는 `policyId, roundId, price, confirmedAt, validUntil`이고 `price`는 WBMB 1개당 USDT 기본 단위(18 decimals)다. 보고자·임계값·`policyId`·`maxAge`·`maxChangeBps`·`minInterval`은 생성자에서 고정되고 변경 함수가 없다. 제출은 누구나 할 수 있다. `IPricePolicy`에는 `validUntil()`이 추가됐다(시장이 가격 중단 대기 시간의 기준 시각으로 읽는다).

`submit` 거부 조건:

| 에러                    | 조건                                                                                  |
| ----------------------- | ------------------------------------------------------------------------------------- |
| `BAD_POLICY`            | 정책 ID 불일치                                                                        |
| `ROUND_GAP`             | roundId가 직전 + 1이 아님 (잘못된 큰 번호로 정책이 영구 정지되는 것 방지)             |
| `BAD_VALIDITY`          | 유효기한이 지났거나 지금 + `maxAge` 초과, `confirmedAt`이 미래이거나 직전 값보다 과거 |
| `BAD_PRICE`             | 0 또는 1e30 초과                                                                      |
| `PRICE_JUMP`            | 직전 가격 대비 변동이 `maxChangeBps` 초과 (첫 보고서는 제외)                          |
| `TOO_SOON`              | 가격이 바뀌는 보고서인데 직전 가격 변경 후 `minInterval` 미경과                       |
| `NOT_ENOUGH_SIGNATURES` | 서명 수가 임계값 미만                                                                 |
| `BAD_SIGNER`            | 보고자 아님 / 중복 / 주소 오름차순 아님 / 다른 체인·컨트랙트·내용에 대한 서명         |

가격이 같은 보고서는 `minInterval`과 무관하게 받는다(유효기한 연장용). `prices()`는 유효기한이 지났거나 보고서가 없으면 `STALE_PRICE`로 실패하고, 아니면 `(체결 기준가, 현재 가격)`을 돌려준다. 체결 기준가는 가격이 바뀐 뒤 `minInterval` 동안은 `min(직전 가격, 현재 가격)`이고 그 뒤에는 현재 가격이다. 첫 값은 체결 시 담보 계산에, 둘째 값은 청산에 쓴다. 배포 값(본 시장): 보고자 1명·임계값 1, `maxAge` 6일, `maxChangeBps` 3000, `minInterval` 12시간(`config/bsc.mjs`의 `BSC.council`). 변동 한도와 간격은 서명 키가 새도 가격을 한 번에 임의 값으로 바꾸지 못하게 하지만, 키를 가진 사람이 12시간마다 30%씩 계속 움직이는 것은 막지 못한다.

### P2PLending 변경 3건

1. **청산 보너스.** 생성자 인자 `liquidationBonusBps`(0~1000). 가격 정산에서 대출자 몫은 `min(담보, 올림(부채 × (1 + 보너스) ÷ 가격))`, 나머지는 차입자. 본 시장 1000(10%).
2. **가격 중단 대비.** 생성자 인자 `staleSettleDelay`(가격 정책이 있으면 1분 이상 30일 이하). 가격 정책이 가격을 주지 못할 때(만료·보고서 없음), 대출 유예 종료(만기 + 유예)와 가격 `validUntil` 중 **늦은 시각**부터 `staleSettleDelay`가 지나면 담보 전부를 대출자에게 준다. 대출 기한만 기준으로 하면 오래 연체된 대출이 중계의 짧은 중단에도 차입자의 초과 담보를 통째로 잃기 때문이다. 가격이 살아 있으면 항상 가격으로 정산한다. 본 시장 7일, 테스트 시장 5분.
3. **유예 하한.** 가격형 시장에서도 유예가 `minGrace` 미만인 게시를 거부한다(`BAD_GRACE`). 보너스가 생겨 1분 늦은 차입자가 보너스만큼(10%)을 잃을 수 있기 때문이다.

그 밖의 동작(게시자가 APR·담보 여유·청산선을 정함, 수수료는 이자의 `feeBps`를 차입자가 추가 부담, 관리자·업그레이드 없음)은 그대로다. 가격이 멈춘 동안에도 상환·담보 추가·취소·수령은 되고 새 체결과 가격 기반 정산만 멈춘다.

생성자는 9개 인자를 받는다. 순서는 다음과 같다.

```text
P2PLending(usdt, wbmb, pricePolicy, feeVault, feeBps, minDuration, minGrace,
           liquidationBonusBps, staleSettleDelay)
```

오라클 없는 시장은 `pricePolicy`가 0 주소이고 마지막 두 인자는 0이다. 크기: `P2PLending` 13,871 bytes, `CouncilPricePolicy` 4,750 bytes(24,576 이내).

### 중계 봇과 배포 스크립트

- `scripts/relay-council.mjs`(판단은 `src/council-relay.mjs`의 순수 함수): 한 번 실행하면 한 번 확인하고 끝난다. API 응답은 15초, 거래 확인은 120초로 제한하고, 넘으면 오류로 끝난다. 형식이 깨진 응답·HTTP/네트워크 오류·미래의 확정 시각·컨트랙트 한도를 넘는 변동에서는 아무것도 보내지 않는다. 이런 상태가 이어지면 온체인 가격이 만료된다. 한도를 넘는 변동은 사람이 `--step`으로 푼다. `planRelay`의 `step`이 참이면 `체인 가격 ± floor(체인 가격 × maxChangeBps ÷ 10000)`을 카운슬 가격 쪽으로 한 단계 보내고, 보고서의 `confirmedAt`은 체인 값을 유지한다(중간 가격은 카운슬 확정이 아니다). `minInterval`과 미래 확정 시각 거부는 그대로다. 타이머에는 넣지 않는다. `artifacts/`(Git 제외)를 읽으므로 새로 받은 저장소에서는 `npm run compile`을 먼저 한 번 실행해야 한다.
- 배포: `deploy:bsc`의 프로필 `council`(`--council`)과 `council-test`(`--council --test-market`)가 가격 컨트랙트를 먼저, 시장을 그다음에 거래 두 건으로 올린다. 두 번째가 실패하면 가격 컨트랙트 주소는 실행 로그에만 남는다. `REPORTER`는 중계 지갑 주소여야 하며 틀리면 고칠 수 없다.
- 화면: 실전 빌드가 시장 종류·시장 주소·가격 컨트랙트 주소·RPC 주소를 굽고, 다른 시장 종류나 가격 컨트랙트, 다른 RPC 주소를 주장하는 `deployment.json`을 거부한다(RPC 고정은 오라클 없는 시장 빌드에도 적용된다). 함께 내려받는 `abis.json`은 고정하지 않았다. 그 파일을 바꿀 수 있는 사람은 번들 자체도 바꿀 수 있기 때문이다.
- 화면의 표준 조건: 카운슬 화면은 조건 한 벌(담보 여유 50%, 청산선 70%, 가격 청산, 유예 1일 — `src/app.js`의 `COUNCIL_TERMS`)로만 게시하고, 같은 정의로 목록을 거른다. 다른 조건의 게시글은 시장 목록에 나오지 않고 화면에서 체결되지 않으며, 올린 사람의 "내 거래"에만 `비표준 조건`으로 나온다. 컨트랙트 수준의 제한은 아니다.

### 컨트랙트가 증명하지 않는 것

- 보고자가 카운슬 가격을 **그대로 옮겼는지**. 서명이 맞고 한도 안이면 받는다. 카운슬 가격을 저장한 온체인 컨트랙트가 없어 이 신뢰를 없애지 못했다.
- 카운슬 가격 **1달러 = 1 USDT**. 둘 중 하나가 깨져도 컨트랙트는 알지 못한다.
- **WBMB 1개 = BMB 1개**. 가격은 BMB에 대한 카운슬 가격이다.
- 받은 WBMB를 부채만큼의 USDT에 팔 수 있다는 것(환금성).
