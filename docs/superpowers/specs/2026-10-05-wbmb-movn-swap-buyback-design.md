# WBMB ⇄ MOVN 직거래 + 수수료 바이백 소각 — 설계 초안

작성일: 2026-10-05 · 상태: **초안 보관, 추후 진행** (사용자 지시 "문서로 만들어서 보관해 추후에 진행"). 승인된 스펙이 아니다. 재개할 때 아래 "남은 질문"부터 확정한 뒤 스펙으로 올린다.

## 1. 목적

1. 대출과 별도로, 사람끼리 WBMB와 MOVN을 직접 사고파는 시장을 연다.
2. 플랫폼 수수료로 들어오는 **모든 MOVN을 시장에서 WBMB로 되사서 소각**한다 — 직거래 수수료와 대출 이자 수수료 모두.

## 2. 사용자 결정 (2026-10-05)

| 항목 | 결정 |
|---|---|
| 직거래 수수료 | WBMB를 **파는 쪽**이 받는 MOVN 대금의 **0.5%** |
| 수수료 처리 | 그 MOVN을 **시장(유니스왑 MOVN/WBMB 풀)에서 WBMB로 되사서 소각** (바이백). 거래 가격으로 바로 환산하는 방식은 택하지 않음 |
| 게시 방향 | 팔기·사기 둘 다 (일부 체결 가능) |
| 대출 수수료 | 대출 이자 수수료(이자의 5%)도 **같이 WBMB로 바꿔 소각** |

## 3. 확인된 사실

- WBMB `0x9e4c…4c86`, MOVN `0x200b…0274` 모두 **burn 함수가 없다** (WBMB 2026-10-01, MOVN 2026-10-04 바이트코드 확인). 소각 = `0x000000000000000000000000000000000000dEaD` 로 전송. 그 토큰은 영구히 쓸 수 없지만 `totalSupply` 숫자는 줄지 않는다. 화면과 문서에 "소각 주소로 보냄"이라고 정확히 적는다.
- MOVN 발행자는 pause / `addToBlacklist` 가 가능하다. 소각 주소나 바이백 컨트랙트가 막히면 그 경로가 멈춘다.
- 유니스왑 v4 MOVN/WBMB 풀(수수료 1000, tickSpacing 10)이 실제 경로이나 **유동성이 얕다** (2026-10-01: PoolManager 전체 WBMB 약 1,528개). 바이백은 조작·샌드위치에 취약하다.
- 대출 컨트랙트의 `feeVault` 는 배포 때 고정이고, `flushFees()` 는 누구나 호출해 MOVN 수수료를 `feeVault` 로 보낸다. 정산 수수료(WBMB)는 `feeVault` 가 `claimWBMB()` 로 직접 찾아간다. → **대출 컨트랙트를 고치지 않고도**, 새로 배포하는 시장의 `feeVault` 를 바이백 컨트랙트로 지정하면 대출 수수료가 바이백으로 흘러간다.
- 저장소에 예전 개념 시험용 `contracts/mocks/MockFeeBurner.sol` (로컬 모의 바이백)이 있다. 실전용이 아니다.

## 4. 구성안 (초안)

### 4.1 `P2PSwap` (신규, 관리자 없음·변경 불가)
- 게시: 팔기("WBMB N개를 개당 P MOVN에 팝니다", WBMB 예치) / 사기("… 삽니다", MOVN 예치). 최소 체결량, 만료일. 가격은 게시 후 변경 불가, 취소만 가능(체결 직전 가격 바꿔치기 방지).
- 체결: 원하는 만큼 일부 체결, 그 자리에서 맞교환. 체결 기한(deadline) 인자.
- 수수료: WBMB 판매자가 받을 MOVN의 0.5% (올림) 를 판매자 몫에서 떼어 **바이백 컨트랙트로 전송**. 예: 10 WBMB × 112 = 1,120 MOVN → 판매자 1,114.4 / 바이백 5.6.
- 안전장치: 잔고 차이로 정확한 전송 확인(대출 컨트랙트와 같은 `_pull/_send` 방식), 재진입 방지, 최소 금액·가격 상한, 수수료율 배포 시 고정.

### 4.2 `BuybackBurner` (신규, 관리자 없음)
- 받는 것: 직거래 수수료 MOVN, 새 대출 시장의 `flushFees` MOVN, 대출 정산 수수료 WBMB(`claimWBMB` 호출).
- `buyAndBurn()` — 누구나 호출. 쌓인 MOVN으로 v4 풀에서 WBMB를 사서 즉시 소각 주소로 전송. WBMB는 그대로 소각 주소로 전송.
- 조작 방지(핵심): 최소 수령량을 **카운슬 가격(`CouncilPricePolicy`)** 기준으로 계산 — 풀 가격이 카운슬 가격보다 X% 이상 비싸면 사지 않는다. 회당 최대 매수량, 최소 간격을 둔다. 실패하면 MOVN은 그대로 쌓여 다음 기회를 기다린다.
- 실행 주체: 주기적으로 `buyAndBurn` 을 부르는 봇(가격 중계 봇과 같은 방식, cron).

### 4.3 기존 대출 시장
- 이미 배포된 시장(`feeVault` = 운영 지갑)은 바꿀 수 없다. 운영자가 수수료 지갑에 쌓인 MOVN·WBMB를 수동으로 바이백 컨트랙트에 보내거나, 새 시장을 `feeVault = BuybackBurner` 로 다시 배포한다.

### 4.4 화면
- 새 탭 "WBMB 사고팔기": 팔기(낮은 가격순)·사기(높은 가격순) 목록, 카운슬 가격 대비 %, 게시 양식, 체결, 내 게시 취소. 확인창에 보내는 것·받는 것·수수료 0.5%(바이백 소각)를 숫자로.
- "소각 내역" 탭: 바이백 컨트랙트에 쌓인 MOVN, 지금까지 산 WBMB, 소각 주소로 보낸 총량.

## 5. 남은 질문 (재개 시 확정)

1. 바이백 가격 보호선: 카운슬 가격 대비 몇 % 이상 비싸면 사지 않을지 (초안: +3%).
2. 회당 최대 매수량·최소 간격 (초안: 회당 50 MOVN, 1시간).
3. 바이백 봇을 어느 PC·지갑에서 돌릴지 (가스비 부담 주체).
4. 풀 유동성이 계속 부족하면: MOVN을 무기한 쌓아 둘지, 대체 경로(MOVN/USDT → USDT/WBMB 등)를 허용할지.
5. 대출 수수료: 새 대출 시장 재배포(`feeVault = BuybackBurner`) 시점, 기존 수수료 지갑 잔액 처리.
6. v4 연동 방식: PoolManager 직접 `unlock` 콜백 vs Universal Router — 감사·검증 부담 차이 (기술 결정, 재개 시 내가 정함).
