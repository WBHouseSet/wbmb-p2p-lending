# 기준 통화 USDT → MOVN 전환 — 설계

작성일: 2026-10-04 · 상태: 사용자 승인(대화) 완료, 문서 검토 대기

## 1. 목적

대출 원금·이자·수수료를 USDT 대신 **MOVN**(BSC `0x200b63aa750c901892d4dcf82439860f9c270274`)으로 주고받는다. 담보는 그대로 WBMB.

사용자 결정(2026-10-04):

- 범위: **전부 MOVN.** 코드·화면·테스트·문서의 기준 통화를 MOVN으로 바꾼다.
- 검증: **로컬 리허설 + 실제 BSC.** 웹페이지로 모든 기능을 확인한다.
- 실거래용 MOVN은 운영자가 소액(10개)을 테스트 지갑에 넣는다.

## 2. MOVN 사실 (2026-10-04 BSC 실측)

- 이름·심볼 MOVN, **decimals 18**, 공급 2억, 프록시 아님(EIP-1967 슬롯 비어 있음).
- owner `0x2d33…b9a4`(발행 가능). `pause()`/`unpause()`와 블랙리스트로 보이는 함수가 있다 → 발행자가 전송을 멈추거나 특정 주소를 막을 수 있다.
- $1 기준가를 지향하는 토큰. 카운슬이 MOVN을 $1로 친다(MOVN→BMB 전환이 카운슬 가격 기준). 시장가 약 1.00~1.007.

## 3. 결정

1. **계산 로직은 그대로.** 생성자의 `decimals() == 18` 검사도 MOVN이 통과한다. 수수료 5%(이자 기준), 대출 한도 50%, 청산선 70%, 청산 보너스 10%, 정산 수수료 규칙 모두 그대로.
2. **가격.** 카운슬 가격(BMB 1개당 USD)을 그대로 "WBMB 1개당 MOVN"으로 쓴다. 근거: 카운슬 자체가 MOVN = $1로 전환한다. MOVN 시장가의 ±1% 괴리는 무시한다.
3. **컨트랙트 이름 변경.** `P2PLending`의 `usdt`·`USDT`가 들어간 식별자를 `movn`·`MOVN`으로 바꾼다(`usdt()`→`movn()`, `claimUSDT`→`claimMOVN`, `claimableUSDT`→`claimableMOVN`, `escrowUSDT`, `totalClaimUSDT`, `_creditUSDT`, 주석·revert 메시지 포함). 새 배포가 필요하므로 ABI가 바뀌어도 잃는 것이 없고, BscScan에 공개될 소스가 실제 토큰과 맞아야 외부인이 의심하지 않는다.
4. **서명 도메인.** 카운슬 보고서의 `policyId`를 `wbmb-usdt/mobick-council/v1` → `wbmb-movn/mobick-council/v1`로 바꾼다. 가격의 의미(단위)가 바뀌었으므로 옛 보고서가 새 시장에 재사용될 수 없게 한다.
5. **설정.** `config/bsc.mjs`의 `usdt`를 `movn`으로 교체. 배포 기록(`deployments/*.json`)의 새 기록은 `movn` 키를 쓴다. 옛 USDT 기록은 손대지 않는다(역사).
6. **화면.** 모든 USDT 표기·안내문·토큰 링크를 MOVN으로. 위험 안내에 "MOVN 발행자는 전송을 멈추거나 주소를 막을 수 있다. 그동안 상환이 막히면 만기 뒤 정산될 수 있다"를 추가.
7. **쓰지 않는 코드.** `SignedPricePolicy`·`report-signing`(폐기된 DEX+LBank 오라클)은 배포되지 않으므로 이름을 바꾸지 않는다. `MockFeeBurner`는 데모 화면이 읽으므로 함께 바꾼다.
8. **기존 미커밋 작업.** 정산 수수료, "직접 확인하기" 블록, 담보 힌트를 테스트로 확인한 뒤 먼저 커밋하고 그 위에서 바꾼다.

## 4. 검증

### 1단계: 로컬 리허설 (비용 0)

- 단위 테스트(`npm test`), 실 바이트코드 테스트(`test:real`: BSC에서 MOVN·WBMB 코드를 복사), 브라우저 테스트(`test:browser`), 실전 화면 리허설(`test:live`)이 모두 MOVN으로 통과.
- 실전 화면 리허설(체인 id 56 복제, 실제 MOVN 바이트코드, 실제 배포 스크립트·중계 봇)에서 웹페이지로 다음을 모두 누른다:
  지갑 연결 · 빌려주기/빌리기 제안 · 수락 · 상환 · 취소 · 수령(MOVN·WBMB) · 만기 연체 정산 · 가격 하락 청산 · 가격 만료 뒤 정산 · 수수료 정리.
  빠진 경로가 있으면 테스트를 추가한다.

### 2단계: 실제 BSC

1. 운영자가 MOVN 10개를 넣는다(받는 곳 index 0 `0xe576…0D59`). index 1에는 index 0에서 MOVN과 BNB를 나눠 보낸다.
2. MOVN 카운슬 테스트 시장 배포(최소 기간·유예 5분, 보고자 index 2) — **배포 직전 사용자 승인**.
3. 첫 가격 중계 후, 공개 사이트를 새 시장 빌드로 바꾼다.
4. 실제 웹페이지에서(자동 브라우저 + 실제 키 지갑) 상환 · 취소 · 연체 정산 · 수령을 소액으로 실행하고 BscScan에서 잔고를 대조한다.

## 5. 옛 시장 처리

- USDT 카운슬 테스트 시장 `0x1099…b217`에 WBMB 0.01이 남아 있다(열린 제안 또는 대출). 공개 사이트를 바꿀 때 옛 화면을 `/usdt-old/`에 남겨 주인이 회수할 수 있게 한다. 주인을 확인해 보고한다.
- USDT 메인 시장 `0xC290…EF73`, 테스트 시장 `0x6A94…D57c`는 비어 있다. 그대로 둔다.
- MOVN 메인 시장은 이번 범위 밖이다. 2단계 통과 뒤 별도 승인으로 배포한다.

## 6. 위험

- MOVN 일시정지·블랙리스트: 상환 불가 → 만기 뒤 정산. 안내문으로 알린다. 수령은 이미 pull 방식이라 한 사람이 막혀도 다른 사람은 영향 없다.
- MOVN 페그 이탈: 가격이 카운슬 $1 가정을 따르므로 MOVN이 $1에서 크게 벗어나면 청산 기준이 틀어진다. 안내문에 가정을 적는다.
