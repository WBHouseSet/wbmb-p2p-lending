# WBMB ⇄ MOVN 직거래 (`P2PSwap`) — 설계

작성일: 2026-10-06 · 상태: 사용자 승인(대화) 완료, 문서 검토 대기

초안 `2026-10-05-wbmb-movn-swap-buyback-design.md` 를 세 덩어리로 나눈 것 중 **첫 번째**다(사용자 결정 2026-10-05: 직거래 먼저).

| 덩어리 | 내용 | 이 문서 |
|---|---|---|
| ① 직거래 | `P2PSwap` 컨트랙트 + "WBMB 사고팔기" 화면 | **범위** |
| ② 바이백 소각 | `BuybackBurner`(소각 + 가스비 BNB) + 실행 봇 + "소각 내역" 화면 | 범위 밖, 별도 스펙 |
| ③ 대출 연결 | `feeVault = BuybackBurner` 인 새 대출 시장 | 범위 밖, 별도 스펙 |

## 1. 목적

대출과 별도로, 사람끼리 WBMB와 MOVN을 직접 사고파는 게시판을 연다. 거래마다 WBMB를 파는 쪽에서 0.5% 수수료(MOVN)를 받는다. 이 수수료를 시장에서 WBMB로 되사서 소각하는 일은 ②에서 한다. ①은 수수료를 **배포 때 고정한 주소로 보내는 것**까지만 한다.

## 2. 사용자 결정

| 항목 | 결정 | 날짜 |
|---|---|---|
| 수수료 | WBMB를 **파는 쪽**이 받는 MOVN 대금의 **0.5%** | 2026-10-05 |
| 게시 방향 | 팔기·사기 둘 다, 일부 체결 가능 | 2026-10-05 |
| 진행 순서 | ① 직거래 → ② 바이백 소각 → ③ 대출 연결 | 2026-10-05 |
| 게시 기간 | 기본 **30일**, 게시자가 **1~90일**에서 선택 | 2026-10-05 |
| 가격 실수 | 컨트랙트는 막지 않는다. **화면이 강하게 경고**하고 한 번 더 확인받는다 | 2026-10-05 |
| 시험 배포 | 실제 BSC 소액 시험용을 먼저 올린다. 수수료 받는 주소 = 기존 수수료 지갑(index 0). 본 배포는 ② 뒤 | 2026-10-06 |

## 3. 확인된 사실

- WBMB `0x9e4c611b834672c3643d9818249366bf65ae4c86`: 8 decimals. MOVN `0x200b63aa750c901892d4dcf82439860f9c270274`: 18 decimals. 둘 다 프록시가 아니고 전송 때 수수료를 떼지 않는다(대출 시장의 정확 전송 검사를 실거래에서 통과, 2026-10-04).
- MOVN 발행자는 전체 정지(pause)와 주소 차단(`addToBlacklist`)을 할 수 있다(2026-10-04 바이트코드 확인).
- 카운슬 가격은 "WBMB 1개당 MOVN"으로 그대로 쓴다. 단위는 1 WBMB(1e8)당 MOVN 최소 단위(1e18 = 1 MOVN). 직거래 가격도 같은 단위를 쓴다.
- 대출 화면은 게시글을 `offerCount` 에서 거꾸로 읽고, 내 게시는 계정별 목록(`offerIdsOf`)으로 읽는다. 직거래도 같은 방식으로 읽는다.

## 4. 컨트랙트 `P2PSwap`

새 파일 `contracts/P2PSwap.sol`. `P2PLending.sol` 은 고치지 않는다. 관리자·업그레이드·임의 인출·수수료 변경 기능이 없다.

### 4.1 고정값 (배포 때 정하고 못 바꿈)

| 값 | 내용 |
|---|---|
| `movn`, `wbmb` | 토큰 주소. 생성자가 decimals 18 / 8 을 확인한다 |
| `feeVault` | 수수료 받는 주소. 0 주소·토큰 주소 거부 |
| `feeBps` | 50 (0.5%). 생성자가 100(1%) 초과를 거부한다 |

### 4.2 게시글

```
Offer { maker, side(Sell|Buy), closed, expiresAt,
        price,          // 1 WBMB당 MOVN 최소 단위
        total, remaining, minFill,   // WBMB 수량
        movnRemaining }              // Buy 게시가 맡긴 MOVN 중 남은 것
```

- `createOffer(side, total, price, minFill, expiresAt)`
  - Sell: WBMB `total` 을 맡긴다.
  - Buy: MOVN `ceil(total × price / 1e8)` 을 맡긴다.
  - 조건: `0 < minFill ≤ total ≤ 1e30`, `0 < price ≤ 1e30`, `now < expiresAt ≤ now + 90일`, 전체 대금이 0보다 큼.
- 가격·수량은 올린 뒤 바꿀 수 없다. 바꾸려면 취소하고 다시 올린다(체결 직전 가격 바꿔치기 방지).
- `closeOffer(id)`: 게시자는 언제든, 만료된 뒤에는 누구나 호출한다. 남은 물건(Sell: 남은 WBMB, Buy: 남은 MOVN 전부)을 **게시자에게** 바로 보낸다.

### 4.3 체결

`fillOffer(id, amount, price, deadline)` — `amount` 는 WBMB 수량.

- 조건: 닫히지 않음, 만료 전, `block.timestamp ≤ deadline`, 인자 `price` 가 게시 가격과 같음, 체결자 ≠ 게시자, `amount ≤ remaining`, `amount ≥ minFill`(남은 수량이 `minFill` 보다 작으면 남은 수량 전부만 가능).
- 대금 `gross`:
  - Sell 게시(체결자가 삼): `ceil(amount × price / 1e8)` — 체결자가 낸다.
  - Buy 게시(체결자가 팖): `floor(amount × price / 1e8)` — 맡긴 MOVN에서 나간다. 마지막 체결 뒤 남는 자투리는 게시자에게 돌려준다.
  - `gross == 0` 이면 거부.
- 수수료 `fee = ceil(gross × feeBps / 10000)`. **판매자 몫에서** 뗀다.

| | Sell 게시 (게시자가 판매자) | Buy 게시 (체결자가 판매자) |
|---|---|---|
| 체결자 → 컨트랙트 | MOVN `gross` | WBMB `amount` |
| 컨트랙트 → 체결자 | WBMB `amount` | MOVN `gross − fee` |
| 컨트랙트 → 게시자 | MOVN `gross − fee` | WBMB `amount` |
| 컨트랙트에 남는 수수료 | MOVN `fee` | MOVN `fee` |

예: 10 WBMB × 112 = 1,120 MOVN → 판매자 1,114.4 MOVN, 수수료 5.6 MOVN.

- 양쪽 토큰은 체결 거래 안에서 바로 상대에게 간다. "수령" 단계는 없다. 대출 시장과 다르게 한 이유: 맞교환은 한 번에 끝나는 거래라 받을 돈을 쌓아 둘 까닭이 없고, 단계가 하나 줄면 화면 실수도 준다.
- 수수료만 컨트랙트에 쌓는다(`feeBalance`). `flushFees()` 는 누구나 호출해 `feeVault` 로 보낸다. 근거: `feeVault`(나중에는 소각 컨트랙트)가 차단되거나 MOVN 수령이 막혀도 체결은 계속돼야 한다.

### 4.4 안전장치

- 토큰 이동은 대출 컨트랙트와 같은 `_pull` / `_send`(보낸 쪽·받은 쪽 잔액 차이가 정확히 그 수량인지 확인). 전송 수수료 토큰으로 바뀌면 거래가 실패한다.
- 모든 상태 변경 함수에 재진입 방지. 상태를 먼저 바꾸고 토큰을 옮긴다.
- 조회: `getOffer`, `offerIdsOf(account)`, `offerCount`, `liabilities()`(맡긴 MOVN + 수수료, 맡긴 WBMB). 시험은 컨트랙트 잔액 ≥ `liabilities()` 를 확인한다.
- 이벤트: `OfferCreated`, `OfferClosed`, `Filled(id, taker, wbmb, movn, fee)`, `FeesFlushed`.
- 컨트랙트는 카운슬 가격을 읽지 않는다. 가격 중계가 멈춰도 직거래는 계속된다.

### 4.5 알고 받아들이는 동작

- MOVN이 전체 정지되면 체결·MOVN 회수가 모두 멈춘다. Sell 게시의 WBMB 취소·회수는 된다.
- 게시자가 MOVN 차단 주소가 되면 그 사람의 게시는 체결되지 않는다(대금을 받을 수 없으므로). 다른 사람의 게시는 영향이 없다.
- 컨트랙트로 직접 보낸 토큰은 회수할 수 없다.
- 게시자의 취소와 체결이 같은 블록에서 겨루면 먼저 들어간 쪽이 이긴다.

## 5. 화면

대출 화면(`index.html`, `src/app.js`)에 탭 **"WBMB 사고팔기"** 를 더한다. 직거래 주소가 설정에 없는 빌드에서는 탭이 나오지 않는다(지금 공개 중인 사이트는 다시 빌드하기 전까지 그대로다).

- **목록.** "팝니다"(싼 순)와 "삽니다"(비싼 순). 카드마다 남은 수량, 개당 가격, 최소 체결량, 게시 만료, **카운슬 가격 대비 ±N%**. 카운슬 가격이 없거나 만료된 시장에서는 비교 표시를 빼고 "기준 가격 없음"이라고 쓴다.
- **게시 양식.** 방향, WBMB 수량, 개당 가격(MOVN), 최소 체결량, 게시 기간(기본 30일, 1~90일). 입력하는 동안 전체 대금을 보여 준다.
- **확인창.** 내가 보내는 것 / 받는 것 / 수수료(0.5%, 금액)를 숫자로. 수수료가 어디로 가는지는 체인에서 읽은 `feeVault` 로 적는다. 시험 배포에서는 "수수료 지갑으로 갑니다"라고 쓰고, 소각한다고 쓰지 않는다.
- **가격 경고.** 나에게 카운슬 가격보다 20% 이상 불리한 가격(팔 때 20% 이상 싸게, 살 때 20% 이상 비싸게)이면 게시·체결 확인창에 빨간 경고 "카운슬 가격보다 N% 싸게 팔게 됩니다 / 비싸게 사게 됩니다"를 띄우고 확인을 한 번 더 받는다. 20%는 화면의 값이다.
- **잔액 확인.** 승인 전에 보낼 토큰의 잔액을 먼저 본다(기존 `approve` 도우미 재사용). 부족하면 얼마가 모자란지 말하고 거래를 보내지 않는다.
- **내 거래.** 내 직거래 게시와 "미체결분 회수" 버튼이 대출 게시와 함께 나온다. 만료됐는데 닫히지 않은 내 게시도 여기서 회수한다.
- **수수료 이동.** 기존 수수료 영역에 직거래 수수료 잔액과 이동 버튼을 더한다.
- **직접 확인하기.** 주소 목록에 직거래 컨트랙트를 더한다.
- 실전 빌드는 대출 주소와 같은 방식으로 직거래 주소·수수료 주소·수수료율을 빌드에 넣어 굽고, 체인에서 읽은 값과 다르면 화면을 열지 않는다.

## 6. 배포와 설정

- 배포 스크립트에 직거래 배포를 더한다. 기록 파일은 **새 파일**(`deployments/bsc-swap-test.json`, 본 배포 `deployments/bsc-swap.json`)이고, 기존 기록 파일은 이름도 내용도 바꾸지 않는다.
- 스크립트는 기존과 같이 `--broadcast` 없이는 예상 비용만 출력하고, 지갑 순번·주소 확인(`DEPLOYER_INDEX` / `DEPLOYER_EXPECT`)을 요구하며, 올린 뒤 설정을 다시 읽어 다르면 실패로 처리한다.
- 실전 빌드(`scripts/build-live.mjs`)는 직거래 기록을 선택 입력으로 받는다. 주지 않으면 지금과 같은 결과가 나온다.
- 로컬 개발(`npm run dev`)과 리허설은 직거래 컨트랙트를 함께 올린다.
- **순서:** 로컬 검증 → (사용자 승인) 시험 배포, `feeVault` = index 0 `0xe576c288b7a714d8a8334255eE5fdbE5de4F0D59` → 실제 BSC 소액 확인 → (사용자 승인) 공개 사이트 재빌드. 본 배포는 ②의 `BuybackBurner` 주소가 생긴 뒤 그 주소를 `feeVault` 로 넣어 한다.

## 8. 남는 위험

- 감사 없음. 컨트랙트는 고칠 수 없으므로 버그가 있으면 새로 배포해야 한다. 소액으로 시작한다.
- 가격 실수는 컨트랙트가 막지 않는다. 화면을 거치지 않고 직접 호출하는 사람은 경고도 받지 못한다.
- MOVN·WBMB 발행자의 권한(정지, 차단, 추가 발행)은 그대로다.
- 거래 상대와 가격은 게시자가 정한다. 컨트랙트는 가격이 적정한지 판단하지 않는다.
- 시험 배포의 수수료는 소각되지 않고 수수료 지갑에 쌓인다. ② 이후 처리는 ②·③ 스펙에서 정한다.

## 9. 범위 밖

바이백 소각, 가스비 BNB 구매, 실행 봇, "소각 내역" 화면, 새 대출 시장, 유니스왑 연동. 주문 자동 매칭(팔기와 사기를 서로 맞붙이는 기능)과 가격 수정 기능도 넣지 않는다.
