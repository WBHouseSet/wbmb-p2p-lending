- 토큰 전송 false/revert와 과세 토큰 거부, 전송 실패 후 claim 보존.
- 재진입 실패의 에러 selector가 `ReentrancyGuardReentrantCall`인지 확인.
- 수수료만 모의 소각기로 이동하고 공급자 수령액/담보는 유지.
- 웹 확인 취소, EIP-1193 계정 변경, 잘못된 체인과 사용자 요청 거부.

## 증거의 범위

실제 로컬 EVM 트랜잭션과 브라우저 동작을 검증했다. 실제 WBMB/USDT, Uniswap·LBank 실시간 가격, 실제 MetaMask/Rabby 확장, 공개 테스트넷/메인넷은 검증하지 않았다. 자동화 지갑 provider는 테스트 구현이다. GitHub Actions 설정 파일은 추가했으나 GitHub 원격 실행은 하지 않았다. 이 검증은 독립 보안 감사가 아니다.

런타임 크기(`npm run compile` 출력): `P2PLending` 13,871 bytes, `CouncilPricePolicy` 4,750 bytes. 둘 다 EIP-170 한도 24,576 bytes 이내. 리뷰 반영에서 `P2PLending.sol`은 주석만 고쳤다. 고치기 전과 뒤의 바이트코드는 길이와 ABI가 같고, 끝의 메타데이터 해시(소스 해시가 들어가는 부분)만 다르다.

`npm run test:real`의 새 시험은 실제 BSC USDT·WBMB 코드를 로컬 체인에 심고 가격형 시장 전 과정을 실행한다. 대출자 제안 게시, 카운슬 가격 100으로 체결(10 WBMB 담보로 600 USDT), 가격 70으로 하락, 정산(대출자가 정확히 9 WBMB, 차입자가 1 WBMB), 각자 수령, 게시 닫기와 USDT 수령 뒤 컨트랙트의 두 토큰 보유량과 장부 부채가 모두 0인지 확인한다. 이 시험이 실패할 수 있음도 확인했다. 기대 수령량을 9에서 8 WBMB로 바꿔 실행하면 `actual: 900000000n, expected: 800000000n` 으로 실패했고, 되돌리면 통과한다.

확인한 경로(가격형 시장, `tests/council.test.mjs`·`tests/council-market.test.mjs`):

- 가격 컨트랙트의 거부 조건(정책 ID, round 순서, 유효기한, 가격 범위, 한 번의 변동 한도, 최소 간격, 서명), 체결 기준가가 가격 변경 직후 낮은 쪽을 쓰는 것.
- 보너스 5%를 포함한 정산(초과 담보는 차입자에게 반환, 담보 부족이면 전부 대출자). 이자가 붙고 나눗셈이 떨어지지 않는 경우도 확인했다. APR 12.37%, 9일 뒤 일부 상환, 연체 뒤 가격 97.31로 정산했을 때 대출자 몫이 시험이 블록 시각과 입력만으로 BigInt로 따로 계산한 `올림(부채 × 1.05 × 1e8 ÷ 가격)`과 같고, 두 몫의 합이 담보와 같고, 모두 수령하고 수수료를 옮긴 뒤 컨트랙트의 두 토큰 보유량과 장부 부채가 0인지 본다. 기대값을 올림 대신 내림으로 바꾸면 최소 단위 1 차이(`441329044n` 대 `441329043n`)로 실패한다.
- 가격이 멈춘 뒤 유예 종료와 가격 유효기한 중 늦은 시각에서 대기 시간이 지나야 담보 전부를 대출자가 받는 것.
- 가격이 만료된 동안: 새 체결(대출 제안·차입 요청 모두)과 체결 견적이 `STALE_PRICE`로 거부되는 것, 상환·담보 추가, 게시 취소와 USDT·WBMB 수령 거래가 그대로 되는 것(수령 뒤 지갑 잔액 증가까지 확인).
- 가격형 시장의 유예 하한, 보너스·대기 시간 한도의 생성자 검사.

중계 봇(`tests/relay.test.mjs`): 판단 규칙(`planRelay`)은 체인 없이 순수 함수로 시험했다(첫 등록, 변경, 대기, 유효기한 연장, 한도 초과 거부와 그 오류 문구, `--step`의 위·아래 한 단계와 내림 처리, 최소 간격 대기, 과거 확정 시각, 한도 안에서는 `--step`이 아무것도 바꾸지 않는 것). 체인과의 동작은 **실제 배포 한도(변동 30%, 간격 12시간, 유효기간 6일)를 가진 가격 컨트랙트를 로컬 체인에 올려** 거래로 확인했다. 가격 변경이 최소 간격 전에는 대기하고 지난 뒤 컨트랙트에 받아들여지는 것, 같은 가격의 갱신이 유효기한을 늘리고 `changedAt`·직전 가격·확정 시각은 그대로 두는 것, 한도를 넘는 변동(110 → 180)을 거부하고 아무것도 보내지 않는 것, `--step` 드라이런이 보낼 값을 출력만 하는 것, `--step` 한 번이 정확히 한도 값(143)에 닿아 컨트랙트가 받는 것(1 단위 큰 값은 `PRICE_JUMP`로 거부), 최소 간격 뒤 보통 실행이 카운슬 가격(180)에 닿는 것. 그 밖에 형식 오류·HTTP 오류·API 무응답·미확인 거래 해시 보고·드라이런 무전송·보고자가 아닌 키와 니모닉 주소 불일치 거부도 로컬 체인에서 확인했다. 실제 카운슬 API는 시험에서 호출하지 않는다.

화면(`tests/browser-council/`, `tests/browser-live-council/`, `tests/browser-live/`): 컨트랙트에 직접 올린 비표준 게시글(담보 여유 40%·청산선 61% 대출 제안, 담보 여유 1% 차입 요청)이 시장 목록에 없고 올린 사람의 "내 거래"에만 `비표준 조건`으로 보이며 회수되는 것, 표준 카드의 청산선 표시, 체결 확인창의 청산선·청산 가격·보너스 문구(대출자 쪽과 차입자 쪽), 첫 가격 전의 `가격 미등록` 표시와 체결 차단, 유예 하한 오류가 컨트랙트의 `minGrace`로 표시되는 것. 실전 모드에서는 게시·체결·담보 추가에 더해 로컬 체인의 시간을 만기 + 유예 뒤로 옮겨 정산하고 확인창의 두 몫(0.63 / 0.37 WBMB)과 보너스 표시를 확인하며, `rpcUrl`만 바꾼 `deployment.json`을 두 시장의 실전 빌드가 모두 거부하는지 본다.

증거의 범위: 메인넷에는 아무것도 전송하지 않았다. 이 시장은 아직 배포하지 않았고, 실제 카운슬 가격 API는 사람이 손으로 읽어 응답 형식을 확인했을 뿐 자동 시험은 모의 응답을 쓴다. 화면의 표준 조건 필터는 화면의 보호일 뿐 컨트랙트의 제한이 아니다. 실제 MetaMask/Rabby 확장과 메인넷 전체 fork, 독립 보안 감사는 하지 않았다. 컨트랙트가 증명하지 않는 것은 [IMPLEMENTATION.md](IMPLEMENTATION.md)와 [MAINNET.md](MAINNET.md) 8절에 적었다.
