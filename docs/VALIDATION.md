## 확인한 중요한 경로

- 양방향 게시와 자금 예치, 부분 체결·잔여 취소·만료 회수.
- 각 체결의 담보 분리, 수량 반올림, 두 토큰 잔액 보존.
- 단리 이자·만기 상한·부분 상환·이자만 납부·수수료 나머지.
- 담보 추가 후 청산 회피, 초과담보 반환, 담보 부족 시 대출자 손실 격리.
- 서명 보고서: 2-of-3 수용, 서명 부족·외부인·중복·다른 도메인·변조·round 재사용·소스 괴리 거부.
- 가격 만료 시 체결/정산 거부, 상환/담보 추가/취소/수령 유지.
- 만기형 전체 담보 귀속과 가격형 임계값 경계/회복 처리.
- 토큰 전송 false/revert와 과세 토큰 거부, 전송 실패 후 claim 보존.
- 재진입 실패의 에러 selector가 `ReentrancyGuardReentrantCall`인지 확인.
- 수수료만 모의 소각기로 이동하고 공급자 수령액/담보는 유지.
- 웹 확인 취소, EIP-1193 계정 변경, 잘못된 체인과 사용자 요청 거부.

## 증거의 범위

실제 로컬 EVM 트랜잭션과 브라우저 동작을 검증했다. 실제 WBMB/USDT, Uniswap·LBank 실시간 가격, 실제 MetaMask/Rabby 확장, 공개 테스트넷/메인넷은 검증하지 않았다. 자동화 지갑 provider는 테스트 구현이다. GitHub Actions 설정 파일은 추가했으나 GitHub 원격 실행은 하지 않았다. 이 검증은 독립 보안 감사가 아니다.

런타임 크기(`npm run compile` 출력): `P2PLending` 13,871 bytes, `CouncilPricePolicy` 4,750 bytes. 둘 다 EIP-170 한도 24,576 bytes 이내.

`npm run test:real`의 새 시험은 실제 BSC USDT·WBMB 코드를 로컬 체인에 심고 가격형 시장 전 과정을 실행한다. 대출자 제안 게시, 카운슬 가격 100으로 체결(10 WBMB 담보로 600 USDT), 가격 70으로 하락, 정산(대출자가 정확히 9 WBMB, 차입자가 1 WBMB), 각자 수령, 게시 닫기와 USDT 수령 뒤 컨트랙트의 두 토큰 보유량과 장부 부채가 모두 0인지 확인한다. 이 시험이 실패할 수 있음도 확인했다. 기대 수령량을 9에서 8 WBMB로 바꿔 실행하면 `actual: 900000000n, expected: 800000000n` 으로 실패했고, 되돌리면 통과한다.

확인한 경로(가격형 시장): 가격 컨트랙트의 거부 조건(정책 ID, round 순서, 유효기한, 가격 범위, 한 번의 변동 한도, 최소 간격, 서명), 체결 기준가가 가격 변경 직후 낮은 쪽을 쓰는 것, 보너스 5%를 포함한 정산(초과 담보는 차입자에게 반환, 담보 부족이면 전부 대출자), 가격이 멈춘 뒤 유예 종료와 가격 유효기한 중 늦은 시각에서 대기 시간이 지나야 담보 전부를 대출자가 받는 것, 가격이 멈춘 동안의 상환·담보 추가·취소·수령, 가격형 시장의 유예 하한, 보너스·대기 시간 한도의 생성자 검사. 중계 봇은 로컬 체인에서 가격 변경·유효기한 연장·과도한 변동 거부·형식 오류·API 무응답·미확인 거래 해시 보고·드라이런 무전송을 확인했다.

증거의 범위: 메인넷에는 아무것도 전송하지 않았다. 이 시장은 아직 배포하지 않았고, 실제 카운슬 가격 API는 사람이 손으로 읽어 응답 형식을 확인했을 뿐 자동 시험은 모의 응답을 쓴다. 실제 MetaMask/Rabby 확장과 메인넷 전체 fork, 독립 보안 감사는 하지 않았다. 컨트랙트가 증명하지 않는 것은 [IMPLEMENTATION.md](IMPLEMENTATION.md)와 [MAINNET.md](MAINNET.md) 8절에 적었다.
